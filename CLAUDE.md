# T1DMAI — Agent Instructions

## Quick start

```bash
pip install torch numpy pytest blosc2  # install (blosc2 is required by the simulator cache path)
python normalization.py                 # must run once before training
python train.py                         # train
python -m pytest tests/ -v -s           # test (-s required: DUMP lines catch silent numerical bugs)
```

**Config is a single plain file.** `config.py` is a **plain file**, not a symlink —
the old `config.balanced.py` / `config.hypo.py` variants are gone, and there is no
separate JSON config tier. All configuration — the real training values
(`batch_size=512`, `num_workers=20`, the Muon/Adam LRs, `lr_min_ratio`,
`patient_uniform_sample_prob=0.5`, the prediction/night horizons) included — lives
directly in `config.py`. The active architecture is set by `D_MODEL` / `N_LAYERS`
(see the current values in `config.py`); edit
`config.py` directly (or via `resize_model.py` for the architecture knobs) rather
than swapping a symlink. The Kovatchev risk transform bakes the clinical hypo>hyper
asymmetry into the loss geometry itself (equal risk-distance is a larger danger at
low BG), so the old focal/composite hypo-weighting is subsumed; the
clinical-composite checkpoint selector is removed and the counterfactual probe is
diagnostic-only (never feeds the loss or selection). The band-edge hypo/hyper detectors and
the Kovatchev risk transform baked into the loss geometry carry the clinical hypo bias
structurally.

## Three spaces and the only two bridges

The whole pipeline lives in exactly three spaces, crossed by exactly two bridge pairs. Mixing them is the highest-severity bug class — track which space every tensor is in.

| space | sole-legal representation |
|---|---|
| (a) normalized z-space | model **inputs** (bg_absolute, carbs, insulin) via `normalization_stats`; the bg input is `z(f(bg))` — Kovatchev risk THEN z-score |
| (b) mg/dL physical | `last_bg`, the true-BG target, **all** clinical metrics, the GUI |
| (c) risk space | model bg **input** (`f(bg)`, before the z-score) and head **outputs** (quantiles, median), the loss terms, the f-transformed target |

- `normalize`/`denormalize` (in `normalization.py`) is the **only** (a)↔(b) crossing. For the bg channel that "physical" side is risk space: `normalize` applies `kovatchev_f` to bg BEFORE the z-score (via `RISK_SPACE_CHANNELS`, which always contains `bg_absolute`), and `denormalize` inverts z THEN `f_inv`. Inputs AND outputs are therefore risk-space — the model never sees raw-mg/dL bg.
- `utils.kovatchev_f` / `utils.kovatchev_f_inv` is the **only** (b)↔(c) crossing. (Kovatchev risk transform, re-anchored to the `[40, 400]` mg/dL device range: `SCALE = 2.2211457449985317`, `POWER = 1.084` (kept), `OFFSET = 5.540076976170212`, re-solved so `f(40) = −√10` and `f(400) = +√10` — the risk `10·f²` saturates at 100 at both rails, and the zero-risk euglycemic center moves from ~112.5 to ~128 mg/dL; verify the constants against a reference in a unit test.)
- `f` on the bg INPUT happens inside `normalize`/`_forward_transform` (once per channel gather); `f` on the TARGET happens exactly once (top of `risk_total_loss`); the anchor `f(last_bg)` is a separate legitimate call on a different tensor. No op crosses any other way.
- **`f`-guard split.** `kovatchev_f(g)` carries a **hard** `assert (g >= BG_CLAMP_MIN - 1e-3).all()` — the UNITS TRIPWIRE; reserve it for controlled callers that must never carry z-space (`f(last_bg)` anchor, re-f of an inverted value, and the bg-input transform inside `normalize`, whose bg is raw post-noise physical mg/dL — Kovatchev `f` clamps it to the physical range internally), so a stray z-scored value (~[-3,3]) trips it loudly. `kovatchev_f_target(g)` (TARGET path only) does a **physical** `g.clamp(BG_CLAMP_MIN, BG_CLAMP_MAX)` BEFORE `f` (warn only if it clamps beyond a small tolerance) — a rare backstop, since the target is the raw post-noise `bg_observed`, provably cache mg/dL. `kovatchev_f_inv(r)` clamps the **risk input first** to `[f(BG_CLAMP_MIN), f(BG_CLAMP_MAX)] = [f(40), f(400)] = [−√10, +√10]` (≈ `[-3.1623, +3.1623]`, SYMMETRIC now), forms the base, `exp`, then clamps the output to `[BG_CLAMP_MIN, BG_CLAMP_MAX]` = `[40, 400]` — kills both the negative-base NaN (r<−12.31) and the fp32 exp overflow.
- `f` is **never** differentiated: targets and `last_bg` are constants; `last_bg` is `.detach()`'d before `f`. `kovatchev_f` imports `BG_CLAMP_MIN/MAX` from `T1DMSIM.simulator`.
- **No input smoother — raw post-noise signals (a-space precondition).** There is no causal smoother anywhere in the pipeline (`utils.causal_smooth` / `causal_anchor`, `data._causal_last_smooth`, `normalization._causal_smooth_channel`, and the `BG_TARGET_SMOOTH_METHOD/WINDOW/POLYORDER` constants are all GONE, and scipy is no longer a dependency). Every signal channel (bg, carb, insulin) enters normalization as the RAW simulator-final post-noise series: bg is only clamped to the physical `[BG_CLAMP_MIN, BG_CLAMP_MAX]` = `[40, 400]` range (via `kovatchev_f`'s internal clamp), and the sparse carb/insulin channels are floored at 0 by the log1p `max(x, 0)`. The SAME raw bg is the model input, the forecast target, AND the `last_bg` anchor — there is no input/target asymmetry and no centered `smooth_bg`. Deployment realism is intrinsic: the live CGM stream is consumed as-is (nothing to reproduce online), and train↔inference share one distribution since the autoregressive roll re-feeds the model's own raw output.

## Architecture gotchas

- **Patch = 6 timesteps = 30 min.** Patches are the attention/loss unit, but each patch carries 6 raw 5-min values per channel — the BG head emits 6 timesteps per patch.
- **Combined insulin = basal + bolus.** The simulator provides them separately; always sum.
- **Attention mask is NOT standard causal.** Bidirectional within context, **bidirectional within prediction** (prediction→prediction is FULL, not lower-triangular — a prediction patch attends to every other prediction patch), context→prediction blocked (no future leak), prediction→context full. Print a small example before trusting it.
- **RoPE base frequency = 1000** (was 10000). Standard RoPE on Q/K in temporal self-attention; the cos/sin tables are built once per forward at the model level and shared across layers.
- **QK-norm KEPT, ALiBi KEPT.** Per-head RMSNorm on Q and K (`q_norm`/`k_norm`) stays; the ALiBi per-head linear-distance bias `−|i−j| × |slope_h|` (added on top of the mask before softmax) stays. The slopes are nn.Parameters initialized as a geometric series; `.abs()` keeps them non-negative. Masked positions are still set to `-inf`.
- **Context window is variable 8–24 h** (`MIN_CONTEXT_PATCHES = 16`, `MAX_CONTEXT_PATCHES = 48` at 2 patches/hour, since `PATCH_SIZE = 6` makes one patch 30 min). Each training sample draws `n_ctx` uniformly in `[MIN, MAX]`; `collate_fn` left-pads to `MAX_CONTEXT_PATCHES` so the prediction horizon is always at the right edge. The simulator's own ACF analysis in `T1DMSIM/diff/README.md` §0.5 puts the pooled-CGM autoregressive signal floor at ~8 h (the `MIN`); 24 h is held as the working ceiling to cover one full per-patient basal cadence (18–30 h) and to preserve GT context through the 8 h night long-horizon rolling validation (`inference.predict_rolling` slides the window once it exceeds `MAX_CONTEXT_PATCHES`). At inference time the model accepts any `n_ctx ≥ MIN_CONTEXT_PATCHES`.
- **No patient embedding.** The model is patient-agnostic — there is no learned patient identity vector and no `patient_seeds` argument to `model.forward()`. Patient identity is implicit in the context window. `compute_patient_seed` still exists, but only as a deterministic key for picking simulator runs in `data.py`.
- **Unified day + night training.** A single model is trained on both day-time and night-time prediction windows simultaneously. Each sample's prediction-zone start is drawn uniformly at random from any patch-aligned position in the trajectory — there is no day/night band restriction. There are no time-of-day input features anymore (the four sin/cos temporal features are removed); day vs night dynamics are learned implicitly from the glucose/carb/insulin trajectory shape alone. The horizon length is set by `PREDICTION_HORIZON_HOURS` in `config.py` (default 2 h); changing it propagates to `PREDICTION_PATCHES = PREDICTION_HORIZON_HOURS × 2` since each patch is 30 min.
- **3 input features, NO mask bits, NO temporal features — the FROZEN index map.** Inputs are `[bg_absolute, carbs, insulin]` (`N_INPUT_FEATURES = 3`). The four sin/cos time-of-day features are REMOVED and `TEMPORAL_FEAT_START` is gone. There are **no mask bits** (`N_MASK_BITS` is removed). `PATCH_DIM = PATCH_SIZE×N_INPUT_FEATURES = 6×3 = 18`. The single shared mapping `CHANNEL_TO_FEAT = {0: 1, 1: 2}` (output-channel → input feat: carb-channel 0 → feat 1, insulin-channel 1 → feat 2) is used by BOTH `data.py` prediction-zone fill and `inference.py` override-write — never two independent `+offset` literals. bg (feat 0) is the SOLE risk-space input: it is `z(f(bg))` (Kovatchev `f` applied before the z-score, handled entirely inside `normalize`/`_forward_transform` via `RISK_SPACE_CHANNELS`); carb/insulin keep log1p+z. The model is **always conditioned**: in the pred zone bg (feat 0) is always zeroed (it is predicted) while carb (feat 1) / insulin (feat 2) ALWAYS carry their true/announced values — there is no masked-vs-revealed input distribution. Cache→input gather (cache channels unchanged): `bg_observed→feat0, total_carb→feat1, total_insulin→feat2`; IS/HGO/exercise are dropped from the input stack (still in the cache for any retained metric). `NON_MASKABLE_FEATS = (0,)` (bg always 0 in the pred zone); `MASKABLE_FEATS = (1, 2)` names the two slots a caller may write.
- **No dynamics output channels.** There is no `N_OUTPUT_CHANNELS`, no per-channel head, no MDN, no IS/HGO/carb/insulin output. The model emits a **single BG quantile head** (below). `bg_delta` is gone everywhere (no input feature, no normalization channel, no `compute_bg_delta`).
- **Single BG quantile head in Kovatchev risk space.** `model.bg_head` is a 3-layer MLP (`Linear(D_MODEL, BG_HEAD_HIDDEN), SiLU, Linear, SiLU, Linear(BG_HEAD_HIDDEN, BG_HEAD_STEP_BASIS_DIM·(1 + 2*N_SPREADS))`, `BG_HEAD_HIDDEN = 1×D_MODEL`, `N_SPREADS = 3`) off each prediction PATCH's hidden state (post `final_norm`; one `D_MODEL` vector per patch). **Smooth-basis step expansion (structural anti-oscillation):** the head emits `K = BG_HEAD_STEP_BASIS_DIM` (default 3) coefficients per channel — NOT `PATCH_SIZE` independent per-step values — and the forward expands them across the `PATCH_SIZE` within-patch timesteps by a FIXED orthonormal `step_basis (S,K)` buffer (`BG_HEAD_STEP_BASIS_TYPE='dct'` low-frequency cosine modes, or `'poly'`) via `head_raw = einsum('sk,bpkc->bpsc', step_basis, coeff)`. With `K < PATCH_SIZE` the highest-frequency (period-2) within-patch mode is unrepresentable, so an intra-patch median zigzag cannot be emitted by construction; `K = PATCH_SIZE` recovers the old fully-free per-step head. Final layer init `normal(std=BG_HEAD_INIT_SCALE=1e-2)`, bias 0 ⇒ small coeffs ⇒ the median == `f(persistence)` at init (the initial forecast is flat from `last_bg`). The resulting `head_raw (B,P,S,1 + 2*N_SPREADS)` is assembled by `utils.assemble_quantiles(head_raw, last_bg_mgdl, carry_spread=0.0)`: col0 = median delta; cols 1..3 = the `τ>.5` spreads (nearest→far .75/.9/.95); cols 4..6 = the `τ<.5` spreads (.25/.1/.05). `anchor = f(last_bg).detach()` (risk, flat across H); `spread = softplus(raw) + BG_QUANTILE_SPREAD_MIN` (`1e-3`, prevents σ-collapse); `q(τ>.5) = m + carry_spread + cumsum(d+)`, `q(τ<.5) = m − carry_spread − cumsum(d−)`; assemble ascending `(B,P,S,7)`. **Median-assembly mode (R3, gated by `BG_HEAD_MEDIAN_MODE` ∈ {`'global'`,`'cumulative'`,`'independent'`}, default `'global'`, NO new params; replaces the old `BG_HEAD_CUMULATIVE_MEDIAN` boolean):** with `delta = head_raw[...,0]`. **`'global'`** (DEFAULT, R3) projects the per-patch delta over the FULL `P*S` horizon onto a fixed low-frequency DCT-II subspace `span(Bg)` (`Bg` orthonormal, `G = BG_HEAD_MEDIAN_GLOBAL_DIM = 6` columns, kind = `BG_HEAD_STEP_BASIS_TYPE`, cached in `utils.get_global_median_basis`): `delta_flat = delta.reshape(B, P*S)` (C-contiguous patch-major, matching `risk_loss._to_patch_major`), `m = anchor + (delta_flat @ Bg @ Bgᵀ).reshape(B,P,S)`. A projection is an **L2 contraction** (`||proj(x)|| ≤ ||x||`), so the per-patch offset `o[p]=m[:,p,0]−anchor` is bounded and non-monotone in `p` — it CANNOT drift/amplify, structurally killing R1's unconstrained-integrator overshoot. Small `G` low-passes the median (the per-patch period-2 / seam sawtooth is unrepresentable), so no seam penalty is needed; C0 seam-continuity and first-step pinning are NOT enforced (intentional — pinning exact C0 caused R1's drift). At init `m≈anchor` (persistence). **`'cumulative'`** (R1 legacy, BIT-IDENTICAL) makes each patch continue from the previous endpoint — `d_rel = delta − delta[...,:1]`, `rise = delta[...,-1] − delta[...,0]`, `o = cumsum(rise, patch dim) − rise` (EXCLUSIVE), `m = anchor + o[...,None] + d_rel` — C0 at every seam, first step pinned to anchor. **`'independent'`** (legacy, BIT-IDENTICAL) is the flat `m = anchor + delta`. The ± band structure is unchanged under every mode, so `median == q_tau[...,3]` and the ascending fan hold; `P==1` clamps `G≤S` (within-patch low-pass, no seams). As the SINGLE chokepoint, the active mode propagates identically through training, `inference.predict`, and `predict_rolling`. **`carry_spread` (risk-space, default 0.0 ⇒ bit-identical to the old behavior; model.py and every TRAINING caller keep the default)** seeds the cumulative-spread base so a rolling forecast can carry its accumulated band width across roll boundaries; only `inference.predict_rolling` passes a nonzero value. `QUANTILE_LEVELS = (.05,.1,.25,.5,.75,.9,.95)`, `N_QUANTILES = 7`. Output is in RISK space; inference owns `f_inv → mg/dL`.
- **Forward signature (FROZEN): `forward(patches, attn_mask, last_bg, return_time=False) -> (q_tau, median)`.** `last_bg` is a required `(B,)` mg/dL tensor (assert shape and `(last_bg >= BG_CLAMP_MIN-1e-3).all()` at the forward top; `.detach()` before `f`). `q_tau` is `(B, PREDICTION_PATCHES, PATCH_SIZE, 7)` in risk space, ascending τ; `median` is `(B, PREDICTION_PATCHES, PATCH_SIZE)` in risk space (`== q_tau[..., 3]`). The opt-in `return_time: bool = False` diagnostic flag defaults to the **bit-identical** `(q_tau, median)` 2-tuple; `return_time=True` returns `(q_tau, median, time_pred)` — `time_pred` the `(B, PREDICTION_PATCHES, TIME_PROBE_N_BINS)` per-patch hour-of-day bin logits, or `None` when `TIME_PROBE_ENABLED` is False (`q_tau`/`median` are computed identically either way; the head never feeds them in the forward, though with `TIME_PROBE_DETACH=False` its loss now co-trains the trunk). There is **no** `return_trend` / `return_alarm` kwarg.
- **No channel cross-attention.** Each transformer block is `temporal_attn(norm1) → FFN(norm2)` — **2 residual writes**, residual init rescale `1/sqrt(2*N_LAYERS)` (was `3*N_LAYERS` for 3 writes). `ChannelCrossAttention` is deleted.
- **fp32 everywhere.** No bf16 autocast anywhere — forward and loss are both fp32. RMSNorm and SwiGLU run native fp32 (no fp32-cast hack). No gradient checkpointing — every block runs its forward once and keeps activations (peak ~4 GB at B=512, trivial against the box's memory).

## Normalization pipeline (highest bug surface)

- **3 channels only.** `CHANNEL_NAMES = [bg_absolute, carb_intake, insulin_combined]` — IS, HGO, and bg_delta are all dropped. `assert len(CHANNEL_NAMES) == n_normalized_leading_cols`.
- **Sparse channels** (`carb_intake`, `insulin_combined`) use log1p: `normalized = (log1p(max(x,0)) - mean) / std`. Denormalize: `expm1(normalized * std + mean)` clamped ≥ 0.
- **BG channel** (`bg_absolute`) is in **Kovatchev risk space**: `normalized = (kovatchev_f(bg) - mean) / std` — the risk transform is applied BEFORE the z-score. Denormalize: `kovatchev_f_inv(normalized * std + mean)`. `normalization.RISK_SPACE_CHANNELS = frozenset({"bg_absolute"})` is unconditional (the single source of truth for which channel crosses (b)→(c) at normalize time); there is **no** `BG_INPUT_RISK_SPACE` flag and **no** raw-mg/dL input branch. The BG input is thus the SOLE risk-space path — the old plain-z-score bg is gone.
- **Inputs are RAW simulator post-noise channels.** The source signals are the simulator-final post-noise series — `data['bg_observed']` (CGM sensor noise applied, not the clean `data['bg']`); `carb_intake`, `insulin_combined` carry the simulator's multiplicative AR(1) σ≈2% absorption noise — consumed directly, with NO smoothing, before normalization (bg clamped to `[BG_CLAMP_MIN, BG_CLAMP_MAX]`; carb/insulin floored at 0). The TARGET path is NOT separate: the same raw bg is both the model input and the forecast label (there is no input/target asymmetry). The live CGM stream is consumed the same way in deployment, so train and inference share one distribution.
- `SPARSE_LOG1P_CHANNELS` in `normalization.py` is the single source of truth. Every normalize/denormalize call site must consult it.
- **Stats fit in risk space (bg) / log1p space (sparse).** `normalization.py` applies `kovatchev_f` to the raw bg (per `RISK_SPACE_CHANNELS`) and `log1p` to the raw sparse channels — no smoothing — then accumulates per-channel Welford stats, so the saved `mean`/`std` live in **risk space (bg) / log1p space (carb, insulin)**, matching exactly what `data.py` feeds the model. There is a **single** stats file `NORM_STATS_FILE = "normalization_stats.json"` (no dual mg/dL-vs-risk file tier); it was REGENERATED for the raw, `[40, 400]`-risk-space bg. It can be produced either by `python normalization.py` or, alongside `meta.json`, by `T1DMSIM/cache_simulator.py`.
- **Regenerating stats is a precondition.** Trimming `CHANNEL_NAMES`, moving bg to risk space, or changing `SPARSE_LOG1P_CHANNELS` / `RISK_SPACE_CHANNELS`, puts the old `normalization_stats.json` in the wrong space. **Delete it and re-run `python normalization.py`** (or rebuild the cache with `T1DMSIM/cache_simulator.py`) to regenerate the 3-key file; its existence is a final-judge gate, not a side effect.
- **Denormalization call sites**: `normalization.py` (normalize/denormalize), `inference.py`, `gui.py`, and `realdata/run_eval.py` (`_denorm_channel`, an independent per-channel inverse consulting `SPARSE_LOG1P_CHANNELS`). (`data.py`'s `__getitem__` only *normalizes* the input stack; `realdata/report.py` and `realdata/figures.py` denormalize transitively via `inference.py`.) Alter the transform for any channel → audit all of them.

## Training invariants

- **fp32 everywhere.** Forward and loss are both fp32 — no autocast, no bf16. No gradient checkpointing (removed — there is ample memory); the isfinite / `_halve_optimizer_state` / `_maybe_restore_from_ema` resilience is kept verbatim (soft-DTW in fp32 can still Inf).
- **NaN propagation, not crash.** A non-finite intermediate must REACH train.py's isfinite / `_maybe_restore_from_ema` guard rather than abort the step inside a deep assert. (a) `dilate.py` keeps only pure SHAPE asserts; its hard FINITENESS asserts (`SoftDTWBatch` forward+backward) are dropped so a non-finite median/cost flows out to the loss. (b) `utils.kovatchev_f_inv` scrubs a non-finite risk input before the clamp so it can never silently emit NaN mg/dL. (c) `utils.ModelEMA.update` skips blending non-finite incoming weights so a single NaN cannot permanently poison the shadow. (d) train.py's resilience guard wraps forward + loss + backward together.
- **Live vs EMA weights**: training runs on live weights; validation runs under EMA shadow (`ModelEMA.apply_to(model)`). Shadow updates only on accepted steps (not NaN/spike skips). Never let EMA feed back into its own updates. **The two Kendall-Gal log-variance parameters are EMA-EXCLUDED** structurally — they live on a separate `KendallGalWeighting` module that is never passed to `ModelEMA` (train.py wraps only `model`), so they are outside the EMA's reach; there is no name filter in `ModelEMA.__init__` (its signature is just `(model, decay)`).
- **Loss = `risk_total_loss(q_tau, median, true_bg_mgdl, weighting)`** (in `risk_loss.py`; `weighting` is the `KendallGalWeighting` module holding the two log-σ params; soft-DTW DP in `dilate.py`). All old terms (β-NLL, MDN, BG-aux, event BCE, focal, trend Huber, alarm) and the β/focal anneals are deleted. The target is f-transformed exactly once, at the top: `y_risk = kovatchev_f_target(true_bg_mgdl)`, shared by the pinball + DILATE terms.
  - **`L_Q` (pinball)** over all `(h, τ)`: `mean rho_τ(y_risk, q_tau)`, `rho_τ(a,b) = (a-b)*(τ − 1[a<b])`. τ=0.5 kept as the pointwise level anchor (complements the warp-invariant DILATE).
  - **`L_D` (DILATE on the median only)**: reshape `median` & `y_risk` `(B,P,S) → (B, P*S)` **C-contiguous (patch-major, step-minor)** via `_to_patch_major` — assert the time axis is monotone. The two sequences are passed to DILATE **uncentred** (NO per-sample time-mean subtraction), so the DILATE gradient carries a level/DC component alongside the shape; pinball `L_Q` is the primary pointwise level anchor. `L_D = DILATE_ALPHA·shape + (1−DILATE_ALPHA)·TDI`. The **shape** term is a DIVERGENCE soft-DTW `sDTW(m,y) − 0.5·sDTW(m,m) − 0.5·sDTW(y,y)` (the self-terms make it ≈0 with ≈0 grad when m==y; the y-self term is a detachable constant). soft-DTW is **vectorized batched** (anti-diagonal, NOT a per-sample Python loop) with a max-subtraction-stabilized logsumexp softmin; cost = squared diff in risk space. **TDI** = `<A,Ω>` (alignment `A=∂sDTW/∂C` vs off-diagonal distance `Ω`) is the directional derivative of the soft-DTW value along `Ω`, computed by a one-sided finite difference `[sDTW(C+ε·Ω)−sDTW(C)]/ε` (`DILATE_TDI_FD_EPS=0.05`) — one extra `SoftDTWBatch` forward reusing the shape `sDTW(C)`; the median gradient is the exact TDI gradient to `O(ε)` and rides on `SoftDTWBatch`'s gradcheck'd backward. The single custom `torch.autograd.Function` is `SoftDTWBatch` (the old second-order `PathDTWBatch` is removed — it was ~45% of the train step). `DILATE_GAMMA = 1.0` is a **softmin-softness knob, NOT an overflow guard**: the single-cell cost peaks at `(f(400)−f(40))² = (2√10)² = 40`, the max-subtracted softmin is overflow-free in fp32 down to γ=1e-3, and soft-DTW is 1-homogeneous in `(cost, γ)`, so γ trades only how sharply the softmin approximates the hard min. `DILATE_ALPHA = 0.5` (equal shape/TDI split).
  - **Kendall-Gal combine** (numerically safe form): `L_KG = 0.5·exp(−2·log_sigma_Q)·L_Q + log_sigma_Q + 0.5·exp(−2·log_sigma_D)·L_D + log_sigma_D`. `log_sigma_Q`/`log_sigma_D = nn.Parameter(zeros(()))` (init `KENDALL_LOGVAR_INIT = 0.0`), clamped `[-7, 7]`, ndim==0 ⇒ AdamW group (never Muon), EMA-excluded. This `L_KG` is the full training total — the former `L_smooth` median-curvature penalty and its `MEDIAN_SMOOTHNESS_*` constants are removed entirely, so there is no extra term (and the older `L_seam` seam-kink penalty stays removed too).
  - **DILATE is training-focused.** It is computed at both training and validation (validation runs at `VAL_BATCH_SIZE`). Pinball is likewise reported (cheap).
- **Raw target — no input/target asymmetry.** The forecast **target** is the raw post-noise `bg_observed` over the pred zone `(B,P,S)`, mg/dL, NOT f-transformed in the batch (f is applied later, once, in the loss) — and it is the SAME raw bg the model receives as input. There is no smoother anywhere and no "input stays raw / target smoothed" asymmetry: bg is only clamped to `[BG_CLAMP_MIN, BG_CLAMP_MAX]`; carb/insulin are floored at 0. The simulator injects per-step noise on all three channels (CGM sensor noise on bg; a multiplicative AR(1) σ≈2% absorption noise on carb/insulin) and IS/HGO — gone from the inputs — drive some structurally-unforecastable BG jitter; the model now learns from the post-noise signals directly. Deployment realism is intrinsic: the live CGM stream is consumed as-is, and the autoregressive roll re-feeds the model's own raw output, keeping train and inference inputs in one distribution.
- **`last_bg`** = the **last context BG INPUT** — the raw value at `pred_start-1`, already present in the context stack. `utils.last_bg_mgdl_from_context(context, stats)` simply denormalizes that last context value, so the TRAIN anchor and the INFERENCE anchor are computed identically (there is no separate `_causal_last_smooth` / `causal_anchor` estimator). Assert the pred zone is the rightmost `PREDICTION_PATCHES`. Causality is intrinsic: the anchor reads only `context[pred_start-1]`, never `>= pred_start`, so it cannot leak future trend. (Night-extended GT for the rolling long-horizon validation is the raw future bg, padded `mode='nearest'` only so the far-horizon endpoint is not distorted by the pad.)
- **Always-conditioned prediction zone — no masking, no reveal.** The pred-zone carb (feat 1) / insulin (feat 2) ALWAYS carry their true (training) / announced (inference) values; bg (feat 0) is always zeroed. There is **no** `reveal_mask`, **no** `loss_mask`, **no** block masking (`BLOCK_MASK_PROB` / `apply_block_masking` gone), **no** `full_conditioning` flag, and **no** Cond/Uncond split. The BG loss runs over the full `(P,S)` horizon; `batch['loss_mask']` is deleted. The what-if capability remains — it is just always-on (the model conditions on whatever carb/insulin the caller writes via the inference `overrides` / `predict_rolling` `overrides_fn` mechanism), not a toggled regime.
- **Carb-noise augmentation removed.** `CARB_NOISE_AUG_*` and `data._jitter_carb_norm` are gone — the carb input is the post-noise simulator value, unjittered.
- **Band-edge hypo/hyper detectors.** The headline clinical `hypo_recall`/`hypo_precision` AND `hyper_recall`/`hyper_precision` (pooled, per-horizon, nocturnal, AND night-onset) key off the **band edges**, not the median. Derive the edges once: `lo_idx = QUANTILE_LEVELS.index(HYPO_ALARM_QUANTILE_TAU)` (`HYPO_ALARM_QUANTILE_TAU = 0.25`, = 2) and `hi_idx = QUANTILE_LEVELS.index(HYPER_ALARM_QUANTILE_TAU)` (`HYPER_ALARM_QUANTILE_TAU = 0.75`, = 4) — never a bare literal; then `pred_lo = kovatchev_f_inv(q_tau[..., lo_idx])` and `pred_hi = kovatchev_f_inv(q_tau[..., hi_idx])` (both asserted in `[BG_CLAMP_MIN, BG_CLAMP_MAX]`). `pred_hypo = pred_lo < BG_HYPO_THRESHOLD` fires whenever the τ=`HYPO_ALARM_QUANTILE_TAU` lower envelope dips below `BG_HYPO_THRESHOLD`; `pred_hyper = pred_hi > BG_HYPER_THRESHOLD` fires whenever the τ=`HYPER_ALARM_QUANTILE_TAU` upper envelope rises above `BG_HYPER_THRESHOLD` — the clinically conservative call on each side. `true_hypo`/`true_hyper` stay off the TRUE bg. **Recall is strict** — `recall = TP/#true`, `TP = #(true_hypo & pred_hypo)` (resp. hyper). **Precision forgives near-boundary false alarms** within `EXCURSION_PRECISION_TOLERANCE_MGDL` (`config.py`, default 10 mg/dL) of the true value — `precision = #(pred & (true | |edge−true|≤tol)) / #pred` (tol 0 ⇒ strict `TP/#pred`) — so CGM sensor noise near a threshold doesn't deflate it; the validation table's precision rows carry a `±k` suffix (recall rows don't). The median-based hypo/hyper numbers may still be reported as diagnostics, but they are not the headline.
- **Sign-balance & inner-50 diagnostics.** Validation adds (diagnostic only, both written to `validation_log.csv` + the console line): `sign_balance@{30,60,120}` = the fraction of true BG strictly below the median, target 0.5 (a directional-bias / mean-collapse witness); `inner50_cov@{30,60,120}` = the empirical coverage of the `[τ.25, τ.75]` inner band, target 0.5 (a calibration check complementing the central-90% coverage row).
- **Counterfactual probe.** `train._run_counterfactual_probe` perturbs the prediction-zone doses vs a baseline forecast and reports — as **uncoloured** validation-table rows (`Counterfactual` section) + `cf_*` CSV columns — whether the model's dose response is physiologically correct (the property that makes the always-on what-if tool trustworthy): `cf_carb_dbg`/`cf_carb_dir` (a `CF_CARB_BOLUS_G` carb bolus must RAISE BG — mean ΔBG>0, fraction-correct-sign), `cf_insulin_dbg`/`cf_insulin_dir` (a `CF_INSULIN_BOLUS_U` insulin bolus must LOWER BG — ΔBG<0), `cf_carb_monotonic`/`cf_insulin_monotonic` (a dose sweep moves BG monotonically — fraction monotone), `cf_hypo_rescue` (fraction of baseline-hypo forecasts that clear hypo once carbs are added), `cf_hyper_rescue` (fraction of baseline-hyper forecasts that clear hyper once insulin is added). Config constants `CF_CARB_BOLUS_G`, `CF_INSULIN_BOLUS_U`. Diagnostic only — never feeds the loss or checkpoint selection.
- **Time-of-day probe (crucial — co-trains the trunk; PER-PATCH categorical).** An auxiliary probe head — **built under a saved/restored RNG state** (its `nn.Linear` construction draws would otherwise land in the main stream *before* `_init_weights` and shift every forecast weight) and **re-inited LAST in `_init_weights`**, so every forecast-weight RNG draw is byte-identical with/without it (I2, regression-tested by `test_probe_construction_preserves_forecast_init_rng`) — classifies the hour-of-day into `TIME_PROBE_N_BINS` circular bins **per prediction patch** (NO mean-pool): a 2-layer SiLU MLP off EVERY prediction-patch hidden state emits `time_pred (B, PREDICTION_PATCHES, TIME_PROBE_N_BINS)` softmax logits, so every per-patch representation the BG head also reads is forced to encode the absolute clock. `TIME_PROBE_N_BINS = round(24 / PREDICTION_HORIZON_HOURS)` (⇒ 12 two-hour bins at the 2 h default), `TIME_PROBE_BIN_HOURS = 24 / N_BINS` tiles 24 h exactly. With `TIME_PROBE_DETACH=False` (crucial) its loss co-trains the shared trunk, forcing those per-patch hidden states to encode circadian phase — the forward `q_tau`/`median` VALUE is unchanged (the head never feeds them in the forward) but the representation is now shaped by the time task. Each patch's target is `(pred_start_hour + p·adv) mod 24` (`adv = PATCH_SIZE·5/60 = 0.5 h` per patch — physical, NOT a config constant), from `batch['bg_formula_data']['pred_start_hour']` (`(B,)` wall-clock hour, already shipped — NO data.py change). **Loss = per-patch CE only, plus a teacher-forced cross-window penalty.** The CE (`utils.time_of_day_bin_ce`, against a **circular SOFT label** — a wrapped-Gaussian over bins, std `TIME_PROBE_LABEL_SMOOTH_BINS` bins, `<=0` ⇒ one-hot) is the sole within-window term: within one 2 h window the P patches share one forward/context and are already clock-consistent through the trunk (ablation: `tod_jump_h ≈ 0.12 h` with or without a within-window advance penalty), so the old inter-patch consistency penalty (`time_advance_consistency_loss`, `TIME_PROBE_CONSISTENCY_WEIGHT`) is REMOVED. A SEPARATE **cross-window** (paired-window) penalty `TIME_PROBE_CROSS_WINDOW_WEIGHT` couples consecutive INDEPENDENT-forward 2 h windows: `data.py` ships `batch['next_window']` (window k shifted forward one horizon on the SAME true trajectory — teacher-forced, NOT autoregressive; bg-zeroed pred zone, SAME `n_ctx` so `attn_mask` is reused; per-sample `valid` flag), train.py runs a 2nd `model.forward(..., return_time=True)` on it, and `utils.time_cross_window_consistency_loss` rotates window k's ORIGIN-patch (patch 0) resultant by `2π·PREDICTION_HORIZON_HOURS/24` and matches window k+1's origin resultant in the raw `(cos, sin)` plane (atan2-free), coupling the two INDEPENDENT clocks so the rolling clock advances by exactly one horizon across the seam. This is NOT redundant (unlike within-window — the two windows are separate forwards). Diagnostic-only: it rides `_tod_extra` (never `risk_total_loss`/`val_loss_total`/selection), is masked by the validity flag, is skipped entirely when the weight is 0 or the probe is off, and its 2nd training forward is subsampled by `TIME_PROBE_CROSS_WINDOW_FRACTION`. Both CE and the cross-window term are scaled by `TIME_PROBE_LOSS_WEIGHT` in the TRAINING backward ONLY — NEVER in `risk_total_loss`, `val_loss_total`, or checkpoint selection (so selection stays on BG accuracy). Helpers `utils.time_of_day_bin_centers` / `time_of_day_bin_target` / `time_of_day_resultant` / `time_of_day_decode_bins` / `time_of_day_bin_ce` / `time_cross_window_consistency_loss` / `time_cross_window_jump_hours` / `time_inter_patch_jump_hours` (the old two-vector `time_of_day_target` / `time_of_day_decode` and the within-window `time_advance_consistency_loss` are deleted); `circular_hour_error` / `circular_hour_residual` / `circular_bias_hours` / `circular_std_hours` stay. **Decode** via `time_of_day_decode_bins(logits, n_bins)` → `(hour, R)`: softmax, form the probability-weighted resultant `(Σp·cosθ, Σp·sinθ)`, read `hour = atan2(sin,cos)` and `R = hypot(cos,sin) ∈ [0,1]` as the confidence/concentration. Headline scalar metrics decode PATCH 0 (comparable to `pred_start_hour`): `tod_mae_h` / `tod_acc_1h` / `tod_acc_2h` / `tod_acc_bin` / `tod_conf` (chance ≈ 6 h / 8% / 17% / 25%), plus the **clock-reliability** rows `tod_bias_h` (signed circular bias — correctable drift), `tod_std_h` (circular-sd precision), `tod_p90_h` (p90 tail error), `tod_gross_rate` (% off >3 h — blunder/phase-slip), and `tod_mae_hiconf` (MAE on the top-half-`R` readings — is the confidence usable as a trust gate), the now-UNPENALIZED within-window witness `tod_jump_h` (`time_inter_patch_jump_hours`: per-sample mean `|inter-patch step − adv|` in hours, target ~0 — CE-only clock stays consistent), and the cross-window witness `tod_xwin_jump_h` (`time_cross_window_jump_hours`: per valid sample `|clock_{k+1,origin} − clock_{k,origin} − PREDICTION_HORIZON_HOURS|` in hours, lower is better — computed via a 2nd forward on `batch['next_window']`). These need the full residual distribution, so `_run_validation` accumulates per-sample decoded-hour + `R` + jump arrays (not running sums) and finalizes once; circular stats via `utils.circular_bias_hours` / `circular_std_hours` / `circular_hour_residual` (proper circular means — naive angle averaging breaks at the 24 h wrap). **Clock-face surfaces (diagnostic-only).** `inference.predict` / `predict_what_if` / `predict_rolling` take a trailing opt-in `return_time=False` — the byte-identical default adds no key; `True` adds a single `time_pred` `(PREDICTION_PATCHES, TIME_PROBE_N_BINS)` per-patch-logit key (roll-0 only for `predict_rolling`, whose later rolls are synthetic re-feeds; `None` when the probe is off). This is the sole plumbing that carries the probe past training validation — `predict_origin_hour` stays the scalar patch-0 reader. The geometry/aggregation math lives in ONE tested numpy place: `utils.aggregate_origin_belief` (the P per-patch beliefs de-rotated by `−p·adv` and fused into one origin-phase belief, agreement self-sharpening) and `utils.clock_wedge_geometry` (a belief → rigid-rotatable y-up unit-disk wedges + resultant hand + rotation-invariant `R`, circular-wrap-safe), consumed by two thin no-math adapters — `gui_renderer.draw_clock_face` (pygame; y-sign flip only) and `clock_face.draw_clock_axis` (matplotlib; y-up as-is). The GUI paints ONE continuous clock that rigidly rotates the aggregated origin belief by the cursor's elapsed offset `2π·t/24`; the metrics curve scripts render the literal P native per-patch clocks (no interpolation). None of it touches the loss, selection, or the `q_tau`/`median` value. Config `TIME_PROBE_*`: `_ENABLED` (False ⇒ head not built, `time_pred=None`, forward bit-identical), `_HIDDEN`, `_DETACH`, `_LOSS_WEIGHT`, `_INIT_SCALE`, `_N_BINS`, `_BIN_HOURS`, `_LABEL_SMOOTH_BINS`, `_CROSS_WINDOW_WEIGHT`, `_CROSS_WINDOW_FRACTION`.
- **Validation rewrite.** `pred_bg = f_inv(median)` is the SOLE pred_bg into the BG metrics (assert it sits in `[BG_CLAMP_MIN, BG_CLAMP_MAX]` at entry). KEEP (now computed from `pred_bg`): `roc_corr` / `trend_gain_beta` / `trend_amp_ratio` / `bg_curve_corr` (mean-collapse detectors — more important now), CG-EGA, Clarke, per-horizon mard/clarke, nocturnal, rolling long-horizon. DELETE: `ci_coverage_95`, `sigma_calibration`, every per-channel NLL/sigma/signal_ratio row, and the whole event-detection block (carb/bolus recall/precision, bolus_mag_relerr, fdr_*, event_corr). ADD: marginal per-(h,τ) coverage `@{30,60,120}` for the central 90% band (τ.05/.95), target 0.90 (MARGINAL-per-step, not joint-over-horizon; uncoloured diagnostic); `inner50_cov@{30,60,120}` (coverage of `[τ.25,τ.75]`, target 0.5); `sign_balance@{30,60,120}` (fraction of true BG below the median, target 0.5); the pinball term (diagnostic, uncoloured); the DILATE term `loss_D` with its `loss_D_shape` / `loss_D_tdi` components (diagnostic, uncoloured — computed on the validation batch at `VAL_BATCH_SIZE`); the **median forecast roughness** `median_roughness` / `median_roughness_far` (risk-space mean `|Δ²median|` over the whole horizon and over the last patch respectively, uncoloured diagnostic — the anti-oscillation witness the headline RMSE structurally masks); the **excursion-amplitude** block `exc_amp_ratio` (`amp@peak`, forecast/true excursion amplitude at the per-window true peak, target band ≈ 1.0 — the headline anti-collapse/over-dispersion witness for the `DILATE_ALPHA`/γ geometry) / `exc_gain_beta` / `exc_corr` / `exc_overshoot_frac` / `exc_undershoot_frac` / `exc_n`, all uncoloured diagnostics; the **conformal coverage probe** (`_conformal_val_probe`, uncoloured) — `conf cov90@peak RAW`/`CAL`, `conf hypo-escape RAW`/`CAL`, `conf_n` — the held-out raw-vs-calibrated excursion-peak band coverage + τ=0.10 hypo-escape, the in-training witness that split-conformal restores coverage (fit on 60% of val windows, measured on the disjoint 40%; empty when <50 windows or <20 excursion windows). `hypo_recall`/`hypo_precision` (off `f_inv(q_tau[τ=.25])`) and `hyper_recall`/`hyper_precision` (off `f_inv(q_tau[τ=.75])`) become **band-edge-based** (see the band-edge detector bullet). `roc_corr`/`roc_rmse`/`trend_gain_beta` stay per-PATCH (30-min) ΔBG. No `g≈1` deployment gain — sim is in-domain. The trend-head NAMING is retired in docs; the metric keys are unchanged.
- **Checkpoint selection (single "best" snapshot).** `t1dmai_best.pt` is saved on the minimum `val_loss_total` (= `risk_total_loss`); the periodic `t1dmai_step_{N}.pt` snapshots are independent. The clinical checkpoint is **removed entirely** — `t1dmai_best_clinical.pt`, `best_clinical_score`, the balanced-clinical-composite selector, its old counterfactual gate (unrelated to the diagnostic counterfactual probe above), and the floor / final-step-for-clinical rules are all gone, along with the `CLINICAL_COMPOSITE_*` constants in `config.py`. The checkpoint carries an `arch_version` / `loss_schema` stamped purely as provenance metadata (which architecture/loss produced the weights); there is no resume / checkpoint-loading path.

Update the header AND the row writer together.
- **Fixed prediction horizon.** Loss is always computed on the full `PREDICTION_PATCHES` output (no curriculum ramp). `PREDICTION_PATCHES` is derived from `PREDICTION_HORIZON_HOURS` in `config.py` — change that, not `PREDICTION_PATCHES` directly.
- **Conformal-calibration partition — ACTIVE.** A third `T1DMDataset` on a disjoint seed band (`master_seed + CALIBRATION_RESERVE_SEED_OFFSET + i` = `+2_000_000`, disjoint from train hashed seeds and normalization's +1M band) feeds split-conformal quantile recalibration of the BG bands; it still touches NEITHER the loss nor the headline validation metrics — only the post-hoc band correction. `calibrate_conformal.py` runs the trained model over it, fits the per-(step,τ) `delta` (`conformal.fit_quantile_conformal`), and writes `ckpt['conformal_delta']` (+`conformal_meta`). The in-training `conf_*` validation probe (below) is a separate held-out witness.
- **Conformal layer (`conformal.py`, pure numpy, mg/dL).** `fit_quantile_conformal(cal_q (N,S,K), cal_true (N,S), levels, median_idx) -> delta (S,K)` — per-(step,quantile) ASYMMETRIC split-conformal: `delta[s,k]` = the side-aware empirical τ-quantile of the residual `true − q_k` (`_conformal_offset`: `ceil((n+1)τ)` for an UPPER edge τ≥0.5, `floor((n+1)τ)` for a LOWER edge τ<0.5 incl. the τ=0.10 hypo edge — `ceil` on a lower edge is anti-conservative; non-finite residuals dropped per (step,level)). `apply_quantile_conformal(q, delta, median_idx)` adds `delta` and re-enforces the three LOAD-BEARING invariants (unit-tested, `tests/test_conformal.py` + `test_conformal_cqr.py`): MEDIAN held FIXED (delta=0 there), fan kept MONOTONE (no crossing), all-zero delta = identity. `band_coverage(q, true, lo_idx, hi_idx) -> (S,)` is a per-step empirical-coverage helper. The delta is mg/dL (downstream of `f_inv`), and must be RE-FIT per target distribution (sim, each real cohort) — validity rests on cal/test exchangeability.
- **Inference / loading conformal wiring.** `inference.predict(..., conformal_delta=None)` and `inference.predict_rolling(..., conformal_delta=None)` recalibrate the band fan (`apply_quantile_conformal`, median untouched); `None` ⇒ bit-identical (`_MEDIAN_IDX` module const). `realdata/report.load_model` attaches `m.conformal_delta = ckpt.get('conformal_delta')` (np array or None) WITHOUT changing its `(model, stats, step)` tuple — the SIM-fit delta, valid for the simulator path only. SIM figures/metrics: `metrics/sim/sim_data.collect_sim_rows(..., conformal_delta=…)` applies it in the single-pass branch only (rolling `row['bands']=None`, the (S,K) delta cannot span `FIG_STEPS`); `collect_sim_windows` keeps RAW bands so the metric-side CQR re-fits on a disjoint sim cal pool (no double-calibration). REAL cohorts RE-FIT per cohort: `realdata/calibrate.Window.bands` (raw `(PRED_STEPS, N_QUANTILES)` fan) + `forecast_bands`, `run_eval._quantile_cqr` fits on the cohort CAL split and reports raw-vs-cal cov90 + τ=0.10 hypo-escape per horizon into `res['conformal_cqr']` (additive; None ⇒ point path untouched), rendered by `report._conformal_cqr_table`.
- **Disjoint cache slabs — no train/val leak.** `data.py` partitions the cache index space into DISJOINT train/val/cal slabs (via a `cache_partition` argument, or by excluding the val/cal `cache_idx` from the train pool) so the `+10M` val / `+2M` cal seed bands can no longer collapse back onto train rows through `patient_seed % pool_size`. The validation datasets train.py builds (the main always-conditioned set, the night-onset set, and any `master_seed + 10_000_000` set) pass `cache_partition='val'`. Disjointness is verified across several master seeds.
- **Rolling prediction BG fill**: `predict_rolling()` is **BG-autoregressive only**. The three-hop re-feed is `median → f_inv → mg/dL → normalize → bg_absolute slot 0`. There is no `bg_delta` slot / rolling buffer (gone) and no dynamics-output write. carb (feat 1) / insulin (feat 2) come from `overrides_fn` if supplied, else the **zero-RAW normalized baseline** — `normalize(0.0)` per channel via `normalization_stats`, NOT `torch.zeros`: a literal z=0 decodes (through the sparse log1p inverse) to ~0.39 g/step carb and ~0.14 U/step insulin, phantom doses that would corrupt a no-dose roll. bg always anchors at the last forecast BG carried across rolls. To keep the band fan from sawtooth-resetting at each roll boundary, the accumulated risk-space spread is carried forward via `assemble_quantiles`'s `carry_spread`. The caller MUST pass `normalization_stats`.
- **Long-horizon validation via rolling — CONDITIONED on announced doses (as everything is).** Single-pass forward only covers `PREDICTION_HORIZON_HOURS`, but the table reports `bg_rmse @{30,60,120}` (all-sample, single-pass) plus the rolling long horizons `bg_rmse @{180,360,480}` (all-sample) and night-only `night_bg_rmse @{180,360,480}m`. The model is always conditioned, so both the single-pass rows and the rolling rows carry the sample's announced future insulin (basal + boluses) and carb curve. To populate the long horizons, `_run_validation` runs `inference.predict_rolling` per validation sample out to `NIGHT_LONG_HORIZON_HOURS` (default 8 h, set in `config.py`); the roll is conditioned via `_make_long_horizon_overrides_fn` (per-roll slices of `bg_formula_data['extended_{carb,insulin}_{norm,raw}']`, written into each next-roll context patch) — the nocturnal-hypo use case knows the programmed basal ahead of time. BG stays **autoregressive** (the model re-feeds its own median; no true BG is observed yet); conditioning the doses is what tames the autoregressive runaway (zero-basal-OOD) an unconditioned roll would suffer. The dataset ships `bg_formula_data['extended_true_bg_trajectory']` (GT at every horizon) and the `extended_{carb,insulin}_{norm,raw}` dose curves. Set `NIGHT_LONG_HORIZON_HOURS == PREDICTION_HORIZON_HOURS` to skip rolling.

- `resize_model.py` — rewrites `config.py` from manual architecture overrides (D_MODEL, layers, heads, patch size, FFN multiplier `--ffn-mult`, BG-head-hidden multiplier `--bg-head-hidden-mult` sizing `BG_HEAD_HIDDEN = k*D_MODEL` for the single BG quantile head, context patches); reports the resulting parameter count (computed, not targeted, from the active `config.py` — the `D_MODEL` / `N_LAYERS` currently in effect)

Every top-level probe also writes its panels to `metrics/figures/` (`time_probe.py` keeps its older `metrics/time_figures/`); the shared chrome — palette, cohort→hue map, mark and label conventions — lives in `metrics/figstyle.py`, which is the single copy: never inline a colour or an rcParam in a probe. A cohort's hue is fixed there and must stay stable across figures, and colour carries ONE job per mark (cohort identity / single-hue ordinal ramp for a dose ladder or density / one hue in two shades for a before-and-after). `metrics/rebuild_all.sh` regenerates the `real/` and `sim/` reports and their figures, plus the seven top-level probes it names (`curves.py`, `curves_sim.py`, `amp_var.py`, `q2_event_response.py`, `whatif.py`, `meal_stats.py`, `time_probe.py`), on the live best checkpoint. **It does not run `augmented/build_report.py`, `augmented/make_comparison_figures.py`, `curves_aug.py`, `shift15.py` or `augexp.py`** — those are invoked individually, and that is a live trap: run the script, then read `metrics/augmented/README.md`, `shift15.json` or `augexp.json`, and you are reading output built against whatever checkpoint was live when someone last ran them by hand. Re-run them alongside it, or state which checkpoint each number came from. `metrics/` holds `real/`, `augmented/`, `sim/` plus this top-level analysis

## Testing

- Run `python -m pytest tests/ -v -s` after every implementation phase.
- The `-s` flag is critical — tests print diagnostic `[DUMP]` lines that catch silent numerical issues.
- Test with `num_workers=0` to avoid multiprocessing issues during debugging.
- Verify the attention mask visually before trusting it.
- Check for NaN after every new component is added.

## Simulator

- Located at `./T1DMSIM/` (read-only). Import: `from T1DMSIM.simulator import T1DMSimulator`.
- Simulator values are in "amount per step" units (grams/step for carbs, units/step for insulin).
- The model works in normalized space. Track which representation you are in at every point.

## Running tests

Do **not** wrap pytest (or any test command) in `timeout`. Some tests in this
repo run long simulator warmups or training-step smoke checks and a hard
timeout will mask real convergence/throughput regressions as spurious failures.
If a test appears to hang, investigate the test itself rather than killing it
with `timeout`.

Use the Bash tool's own `timeout` parameter (in milliseconds) only when you
genuinely need a wall-clock limit on a long-running command, never to
short-circuit a test.
